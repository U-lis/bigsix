# 0.5.0 — 커스텀 프로그램 (#13) · 단계 조정 이력 (#4)

마일스톤: GitHub `0.5.0`. 브랜치: `feature/custom-program`.

## 요구

- **#13** 사용자가 요일마다 할 종목을 직접 골라 주간 프로그램을 만든다. 만든 프로그램으로
  오늘 화면 · 기록 · 운동일 알림이 기존 5종과 똑같이 돈다.
  예: 월 푸시업 / 화 레그 레이즈 / 목 풀업 / 금 스쿼트 → 주 4일.
- **#4** 단계 수동 조정은 단계 화면에 이미 있었다 (`setStep` · 「단계 조정」). 미결이던
  「조정 이력」만 이번에 한다.

## 결정 (2026-10-29, 사용자 확인)

| # | 질문 | 결정 |
|---|---|---|
| D-1 | #4 범위 | 조정 이력을 남기고 기록 탭(날짜별 · 종목별)에 보인다. JSON 내보내기에 포함 |
| D-2 | 배치 규칙 | 자유 배치 — 요일마다 종목 0개 이상, 같은 종목 여러 요일 가능, 운동일 최소 1일 |
| D-3 | 저장 · 수정 | 여러 개 저장. 한 번이라도 구간에 쓴 프로그램은 고치기 · 지우기 불가 — 복제해서 새로 만든다 |
| D-4 | 자동 전환 제안 | 커스텀 프로그램에서는 내지 않는다 |

D-3 근거: `reviewDay` 는 지난 날의 계획을 그날 구간의 요일표에서 다시 계산한다. 쓰던 요일표를
고치면 지난 날의 수행 · 미수행 판정이 바뀐다.

## 설계

- **저장 모양** — `AppState.customPrograms?: Program[]`. 카탈로그 5종과 같은 `Program` 모양이고
  id 는 `custom-N`. 세트 표기는 빈 문자열 — 세트 수는 기준표가 정한다(기존 5종의 세트 표기도
  계획 계산에 쓰이지 않는다).
- **합친 카탈로그** — 도메인 `withCustomPrograms(catalog, state)`. UI 는 `catalogFor(state)`
  (`$lib/data/catalog`, 같은 배열이면 같은 객체를 돌려줘 `$derived` 를 흔들지 않는다).
  `catalog` 를 받는 기존 함수(계획 · 구간 · 기록 조회 · 제안 · 알림 meta) 는 손대지 않는다.
- **제안 없음** — `nextProgramId` 가 `PROGRAM_ORDER` 밖 id 에 null 을 돌려줘 `proposeSwitch` 가 첫
  단계에서 끝난다. 추가 코드 없음.
- **알림** — cron · 릴레이는 그대로. 구독 meta 의 `program` · `days` 가 커스텀 요일표에서 나온다.
- **조정 이력** — `AppState.stepAdjustments?: { date, progressionId, from, to }[]`.
  `setStep(state, catalog, id, step, onDate?)` 가 `onDate` 를 받았을 때만 쌓는다. 표시 전용이고
  판정 범위는 기존 `adjustedAtSessionIndex` 가 정한다.
- **저장 스키마** — AppState 봉투 v4 → v5, 마이그레이션 no-op. 버전을 올린 이유: 0.4.x 앱은
  커스텀 id 를 몰라 `getProgram` 이 예외를 던진다. future-version 으로 멈추고 덮어쓰지 않는 쪽이
  안전하다. 형태 검사: 두 필드는 있으면 배열, 커스텀 원소는 `custom-` id · name · 7요일 schedule,
  구간이 가리키는 커스텀 id 는 목록에 있어야 한다(없으면 corrupt).
- **화면** — 프로그램 화면 아래 「내 프로그램」. 카드 모양은 5종과 같고 요일표 한 줄이 더 붙는다.
  「새 프로그램 만들기」 · 「고치기」 · 「복제」 · 「지우기」. 5종에도 「복제해서 내 프로그램 만들기」.
  폼은 모달(자유 운동 폼과 같은 틀), 요일 7칸 × 종목 6개 토글(✓ 문구 + aria-pressed).
  잠긴 종목도 넣을 수 있다 — 그날 카드에 잠김으로 선다(5종과 같은 동작).

## 범위 밖
