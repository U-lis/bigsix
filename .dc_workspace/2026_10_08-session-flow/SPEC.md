## Overview

**Purpose**
오늘 화면에서 여러 종목을 번갈아 하더라도 확정한 세트가 지워지지 않게 하고,
그날 운동을 한 번에 마치게 한다.

**Problem**
진행 중 세션을 담는 칸이 앱 전체에 하나뿐이다 (`bigsix.session.inprogress`,
`src/lib/ui/state/storage.ts:24`). 다른 종목에서 세트를 시작하면 `inProgress.begin()`
(`src/lib/ui/session/session.svelte.ts:71`)이 칸을 통째로 덮어써, 앞 종목에서 확정한 세트가
사라진다. 두 종목을 한 세트씩 번갈아 하는 사용자는 기록이 계속 지워진다.
또 종목마다 「세션 완료 기록」 · 「불가능」 버튼이 있어 끝내는 방법이 여러 개이고,
「불가능」이 세트 하나의 실패처럼 읽혀 의미가 헷갈린다.

**Solution**
진행 중 기록을 종목별 칸으로 나눈다. 종목 카드는 세트를 쌓기만 하고, 화면 하단
「오늘 운동 마치기」 하나가 모든 종목을 한 번에 기록 · 판정한다. 계획보다 많이 한 세트는
같은 종목 · 단계의 **자유 운동**으로 기록해 판정에서 뺀다 — 도메인에 이미 있는
`kind: 'free'` 를 쓰므로 도메인은 바꾸지 않는다.

## Functional Requirements

### FR-39: 종목별 진행 중 기록

- [ ] FR-39.1: 진행 중 기록을 **종목별 칸(draft)** 여러 개로 보관한다. 칸의 키는 「종목 + 성격」
      — 계획 칸(`work` · `consolidation`)과 자유 운동 칸(`free`)은 같은 종목이어도 따로다 (EC-99).
- [ ] FR-39.2: 한 종목에서 세트를 확정해도 다른 종목 칸은 그대로다. 종목을 오가며 번갈아 확정할 수 있다.
- [ ] FR-39.3: 칸마다 시작 시점 계획 스냅샷(`target` — 기존 FR-28.3)과 시작 날짜를 담는다.
- [ ] FR-39.4: 세트를 확정 · 수정 · 삭제할 때마다 즉시 저장한다 (기존 FR-2.3 과 같은 원칙).
- [ ] FR-39.5: 확정 세트는 마치기 전까지 값 수정 · 삭제할 수 있다 (J-6). 세트별 RPE 도 같은 방식.
- [ ] FR-39.6: 계획 세트 수를 넘어 세트를 계속 확정할 수 있다. 넘는 세트는 카드에서 「추가 세트」 로 구분해 보인다 (J-2).

### FR-40: 미달 세트 표시

- [ ] FR-40.1: 확정 세트 값이 그 세트의 목표보다 작으면 세트 줄에 「{값} / 목표 {목표} · 미달」 을 글자로 보인다.
      색만으로 알리지 않는다 (CLAUDE.md).
- [ ] FR-40.2: 미달 세트도 그대로 기록되고, 판정은 기존 도메인 규칙(`meetsStandard`)이 한다. 화면이 판정을 대신하지 않는다.

### FR-41: 「이 단계 중단」 (기존 「불가능」)

- [ ] FR-41.1: 버튼 이름을 「이 단계 중단」 으로 바꾸고, 확인 문구에 「지금까지 한 세트를 중단 기록으로
      남기고, 가능하면 이전 단계 다지기를 제안합니다」 를 적는다.
- [ ] FR-41.2: 누르면 즉시 기록하지 않는다. 그 칸에 「중단」 표시를 하고(취소 가능), 마치기 때
      `abandonChallenge` 로 기록한다 (J-5).
- [ ] FR-41.3: 이전 단계로 내려갈 수 있으면(도메인 `canConsolidate`) 그 자리에서 다지기를 제안한다.
      승인하면 같은 종목에 **다지기 칸**을 열어 이어서 세트를 쌓는다. 마치기 때 중단 기록 → 다지기 기록
      순서로 남긴다. 다지기 계획은 도메인 `planConsolidation` 으로 만든다 (도메인 무변경).
- [ ] FR-41.4: 1단계처럼 내려갈 단계가 없으면 제안하지 않는다 (기존 EC-9).

### FR-42: 「오늘 운동 마치기」

- [ ] FR-42.1: 오늘 화면 하단에 「오늘 운동 마치기」 버튼 하나를 둔다. 종목 카드의
      「세션 완료 기록」 버튼은 없앤다.
- [ ] FR-42.2: 확정 세트가 있거나 「중단」 표시가 있는 칸이 하나라도 있을 때만 활성.
      비활성은 투명도 + 커서 + `disabled` (CLAUDE.md).
- [ ] FR-42.3: 누르면 확인 화면에 칸별 요약을 보인다 — 「{종목} {단계}: 정규 N세트 · 추가 M세트」,
      「중단」, 「다지기 N세트」, 「자유 운동 N세트」. 사실만 적는다.
- [ ] FR-42.4: 확인하면 칸마다 도메인 함수로 기록한다.
      - 계획 칸(work): 앞 N세트(N = 계획 세트 수)는 `applySession`(kind `work`),
        N 을 넘는 세트는 같은 종목 · 같은 수행 단계의 `kind: 'free'` 로 기록 (J-2)
      - 계획 칸(consolidation): 앞 N세트는 `recordConsolidation`, 넘는 세트는 `free`
      - 「중단」 칸: `abandonChallenge` (입력한 세트 전부)
      - 자유 운동 칸: `applySession`(kind `free`)
      - 세트가 0개인 칸은 기록하지 않는다 (EC-89)
- [ ] FR-42.5: 기록 순서는 화면 위에서 아래(계획 순서), 자유 운동은 마지막. 각 기록은 직전 기록이
      반영된 상태 위에서 한다. 계획(목표)은 칸을 시작할 때의 스냅샷을 쓴다 (EC-100).
- [ ] FR-42.6: 기록에 성공한 칸만 진행 중 칸에서 지운다. 실패한 칸은 남겨 다시 시도할 수 있게 하고,
      실패 사실을 글자로 보인다 (EC-96).
- [ ] FR-42.7: 기록 뒤 승급 · 보류 · 다지기 결과는 기존 결과 표시 방식으로 보인다.

### FR-43: 자유 운동

- [ ] FR-43.1: 「자유 운동 기록」 폼은 즉시 기록하지 않고 자유 운동 칸을 연다. 세트는 같은 방식으로
      쌓고 같은 마치기로 기록한다 (J-7).
- [ ] FR-43.2: 잠긴 종목은 기존처럼 고를 수 없다 (기존 FR-18.3).

### FR-44: 날을 넘긴 미완료 기록

- [ ] FR-44.1: 진입 때 오늘보다 이른 날짜로 시작한 칸이 있으면 「{날짜} 미완료 기록이 있습니다 —
      그 날짜로 기록 / 버리기」 를 묻는다 (J-3). 기존 「이 세션은 {날짜} 세션입니다」 안내를 대신한다.
- [ ] FR-44.2: 「그 날짜로 기록」 은 FR-42.4 와 같은 규칙으로, 칸의 시작 날짜를 기록 날짜로 쓴다.
- [ ] FR-44.3: 「버리기」 는 확인을 한 번 더 받은 뒤 그 날짜 칸을 지운다.
- [ ] FR-44.4: 답하기 전에는 오늘 칸과 섞이지 않는다 — 지난 날짜 칸은 오늘 계획 카드에 나타나지 않는다.

### FR-45: 저장 스키마 v5

- [ ] FR-45.1: 진행 중 저장을 「칸 하나」 에서 「칸 목록」 으로 바꾼다. `CURRENT_SCHEMA_VERSION` 4 → 5.
- [ ] FR-45.2: v4 의 진행 중 세션 하나는 v5 칸 목록의 원소 하나로 옮긴다 (EC-98). AppState 쪽 v4 → v5 는 no-op.
- [ ] FR-45.3: 미래 버전 · 손상 처리는 기존 규칙 그대로 (FR-1.5 · FR-1.7).
- [ ] FR-45.4: 진행 중 칸이 하나라도 있으면 가져오기(JSON)를 막는다 (기존 규칙을 칸 목록으로 확장).
- [ ] FR-45.5: 전체 초기화는 모든 칸을 지운다.
