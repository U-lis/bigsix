**Target Version**: 0.2.0 (추가분)
**Work Type**: feature
**Base Branch**: `feature/ui` (`14bbaba`)
**선행 SPEC**: `.dc_workspace/2026_09_04-ui/SPEC.md` — 이 문서는 그것을 **대체하지 않고 잇는다.**
확정 사항 D-1~D-19, NFR, 알려진 한계는 전부 유효하다.

## Overview

**Purpose**
1차에서 앱이 실제로 배포되어 돌기 시작했다. 폰에 설치해 쓰면서 드러난 것 세 묶음을 채운다 —
설치·표시·화면 유지 같은 **앱 껍데기의 기본기**, 첫 화면이 상태를 말해주지 않는 문제,
그리고 **휴식일에 할 게 없다**는 문제.

**Problem**

*(1) 앱 껍데기가 비어 있다.* CubeStudy 는 상단 바에 설치 버튼·테마 토글·화면 유지 토글을
갖고 있는데 bigsix 에는 없다. 셋 다 이미 검증된 구현이 옆 저장소에 있다.

*(2) 첫 화면이 상태를 말하지 않는다.* 프로그램 미선택이면 지금은 화면이 리다이렉트만 하고,
휴식일에는 안내가 부실하다. 더 나쁜 경우가 있다 — **잠긴 종목만 배정된 날**이다.

```
veterano, 전 종목 2단계 (브리지·핸드스탠드 잠김)
2026-09-08 화  rest=false  운동=-  잠김=bridge  reviewDay.status=rest
2026-09-09 수  rest=false  운동=-  잠김=hspu    reviewDay.status=rest
```

`planOn().rest` 는 "요일표에 항목이 있는가" 만 본다(`schedule.ts` 의 `rest: entries.length === 0`).
잠겨서 빠진 것과 원래 없는 것을 구분하지 못한다. 반면 `reviewDay().status` 는 잠긴 종목을
`planned` 에서 빼므로 `'rest'` 가 된다. **두 API 가 서로 다른 답을 준다** (1차 SPEC 의 한계 L-3).

화면에서는 휴식일 문구도, 운동 카드도 없이 **잠긴 카드 하나만** 뜬다.
베테랑은 주 6일인데 화·수가 브리지·핸드스탠드 단독이라 잠긴 동안 **실질 주 4일**이 된다.
`good_behavior` 는 금요일 하루가 그렇다.

*(3) 휴식일에 아무것도 못 한다.* 프로그램이 쉬라고 한 날에도 뭔가 하고 싶을 때가 있는데,
기록할 방법이 없다. 하면 기록에 안 남고, 안 하면 그만이다.

**Solution**
상단 바 3종을 CubeStudy 에서 이식하고, 오늘 화면이 **네 가지 상태를 모두 말하게** 하고,
자유 운동 기록을 추가한다. 자유 운동은 도메인 변경을 요구한다 (D-19 에 따라 허용된다).

그리고 규칙의 결과가 실제로 말이 되지 않았다 — 낮은 단계의 **승급 기준 수치**를 그대로

## Functional Requirements

### FR-16: 상단 바 (설치 · 테마 · 화면 유지)

- [ ] FR-16.1: 레이아웃 상단에 바를 두고 아래 세 컨트롤을 배치한다.
      1차에서 만든 하단 탭(오늘 / 프로그램 / 단계)은 그대로 둔다.
- [ ] FR-16.2: **설치 버튼** — `beforeinstallprompt` 를 가로채 보관했다가 버튼을 눌렀을 때
      `prompt()` 를 부른다. 이벤트가 오지 않으면(조건 미달·이미 설치됨·iOS Safari)
      **버튼을 아예 그리지 않는다.** `appinstalled` 에서 보관분을 버린다.
      `prompt()` 는 이벤트당 한 번만 쓸 수 있으므로 호출 즉시 보관분을 비운다.
- [ ] FR-16.3: **테마 토글** — `system` / `light` / `dark` 를 순환한다.
      `system` 이면 `documentElement.dataset.theme` 를 **지우고**, 아니면 그 값을 넣는다.
      선택은 localStorage 에 저장한다.
- [ ] FR-16.4: CSS 는 `prefers-color-scheme` 기본값 위에 `[data-theme="..."]` 가 덮는 구조여야
      한다. 색을 미디어 쿼리 안에서만 정의하지 않는다 — 토글이 양방향으로 이겨야 한다.
- [ ] FR-16.5: **화면 유지 토글** — Screen Wake Lock. 켜짐 상태를 저장한다.
      `navigator.wakeLock` 이 없으면 **토글을 그리지 않는다** (FR-16.7 참조).
- [ ] FR-16.6: 화면이 가려지면 브라우저가 잠금을 놓는다. `visibilitychange` 로 **다시 잡는다.**
      다시 잡지 않으면 한 번 꺼진 뒤로 영영 안 걸린다.
- [ ] FR-16.7: 잠금 요청은 거부될 수 있다(절전 모드 등). 거부돼도 토글은 켜진 채로 두고
      다음 기회에 다시 시도한다. **"켜달라고 한 상태" 와 "실제로 잡혀 있는 상태" 를 구분**한다.
- [ ] FR-16.8: 셋 다 localStorage 접근이 막혀 있어도(EC-5) 앱이 죽지 않아야 한다.
      읽기·쓰기를 각각 try/catch 로 감싼다. 저장에 실패해도 그 세션에는 적용된다.
- [ ] FR-16.9: 구현은 CubeStudy 를 준용한다 —
      `~/Documents/cube-study/src/lib/ui/wakelock.svelte.ts`,
      `settings.svelte.ts` 의 `theme` / `cycleTheme`,
      `src/routes/+layout.svelte` 의 `installPrompt` / `install()`.
      **복사가 아니라 이식이다.** bigsix 에 없는 설정 항목까지 끌어오지 않는다.

### FR-17: 오늘 화면이 상태를 말한다

- [ ] FR-17.1: **첫 화면은 오늘 세션이다.** 프로그램 미선택이어도 프로그램 선택 화면으로
      **자동 이동하지 않는다.** 1차의 FR-3.3(“프로그램 선택 화면으로 보낸다”)을 이 항목이 대체한다.
- [ ] FR-17.2: 오늘 화면은 다음 **네 상태**를 구분해 표시한다. 어느 경우에도 빈 화면이 아니다.

| 상태 | 판정 | 표시 |
|---|---|---|
| 미선택 | `planOn` 이 `{ kind: 'no-program' }` | "선택한 프로그램이 없습니다" + 「프로그램 선택하기」 |
| 휴식일 | `rest === true` | "오늘은 휴식일입니다. 다음 루틴은 **N월 N일(요일)**에 시작됩니다" |
| 할 게 없음 | `rest === false` 인데 `exercises` 가 빔 | 잠김 사유 + **휴식일과 같은 안내** (FR-17.5) |
| 운동일 | `exercises` 가 있음 | 1차 FR-5 그대로 |

- [ ] FR-17.3: 「프로그램 선택하기」 버튼은 프로그램 선택 화면으로 보낸다 (E-5).
- [ ] FR-17.5: **`rest` 의 정의를 바꾸지 않는다.**
      `rest` 는 `schedule.ts:52` 의 `entries.length === 0` 하나로 정해지며 뜻은
      **"프로그램이 쉬라고 정한 날"** 이다. 판정 로직 중 `rest` 를 읽는 곳은 없고 표시에만 쓰인다.
      잠겨서 빈 날은 프로그램이 쉬라고 한 것이 아니므로 `rest === false` 가 그대로 옳다.
      **「할 게 없는 날」은 `rest === false && exercises.length === 0` 으로 화면이 파생한다.**
      도메인 변경이 필요 없고, 두 경우를 다르게 말할 수 있다는 이점도 유지된다.
- [ ] FR-17.6: 1차의 한계 **L-3**(`planOn().rest` 와 `reviewDay().status === 'rest'` 는 다르다)은
      해소하지 않고 **그대로 둔다.** 둘은 서로 다른 질문에 답한다 —
      `rest` 는 "프로그램이 배정했는가", `status` 는 "결과적으로 할 것이 있었는가" 다.
      L-3 의 설명을 이 구분이 드러나도록 다듬는다.
- [ ] FR-17.4: **다음 운동일 계산은 잠금을 알아야 한다.**
      현재 `firstTrainingDay(catalog, programId, from)` 는 `state` 를 받지 않아 잠금을 모르고,
      전부 잠긴 날을 "다음 운동일" 로 가리킬 수 있다.
      **`state` 를 받아 실제로 수행할 종목이 있는 날을 돌려주는 경로**가 필요하다.
      기존 함수를 바꿀지 새로 둘지는 설계가 정한다 — 기존 호출부(프로그램 선택 화면의
      "다음 첫 운동일이 1일차" 안내)가 무엇을 기대하는지 읽고 판단하라.
- [ ] FR-17.4a: 7일을 다 봐도 수행할 것이 있는 날이 없을 수 있다 (빅4 가 낮아 브리지·핸드스탠드가
      전부 잠긴 `veterano` 는 아니지만, 요일표 구성에 따라 가능하다). 이때 **예외를 던지지 말고**
      "당분간 수행할 종목이 없다" 를 화면이 말할 수 있어야 한다 (EC-43).
- [ ] FR-17.7: 문구는 사실만 적는다 (NFR-2). "푹 쉬세요" 같은 말을 넣지 않는다.

### FR-18: 자유 운동 기록 (도메인 변경)

- [ ] FR-18.1: 자유 운동은 **언제든** 기록할 수 있다 (E-7). 휴식일·운동일을 가리지 않는다.
      계획된 운동과 섞여도 `kind: 'free'` 로 구분되므로 따로 관리된다.
- [ ] FR-18.2: 입력 항목은 **종목 · 단계 · 난이도(기준) · 세트별 수치**다.
      단계는 1~10, 난이도는 초보자 / 중급자 / 상급자(또는 최상급자) 중 하나다.
      선택한 단계·난이도의 기준 수치가 입력란 초기값이 된다 (1차 FR-6.2a 와 같은 방식).
- [ ] FR-18.3: 잠긴 종목은 자유 운동으로도 할 수 없다. `checkGate` 판정을 그대로 쓴다.
      **자유 운동이 해금 우회 경로가 되면 안 된다** (1차 FR-13.5 와 같은 원칙).
- [ ] FR-18.4: **⚠ 단계가 조용히 내려가는 경로를 반드시 막는다.**
      `evaluate.ts:78` 은 승급하지 않으면 `nextStep = record.step` 을 돌려주고,
      `applySession` 이 그 값을 `state.steps[id]` 에 그대로 쓴다.
      현재 7단계인 종목을 자유 운동으로 3단계에 기록하면 **단계가 3으로 내려간다.**
      이것은 강등이 아니라 사고다. **자유 운동은 `state.steps` 를 어느 방향으로도 움직이지 않는다.**
      기존 `consolidation` 분기가 `nextStep = record.step` 을 돌려주는 것은 다지기의 `step` 이
      곧 현재 단계라서 성립하는 것이고, 자유 운동은 사용자가 단계를 고르므로 같은 처리를 쓰면 안 된다.
- [ ] FR-18.5: 자유 운동 기록은 `history` 에 남고 수행 이력으로 조회된다.
- [ ] FR-18.6: **자유 운동은 진행 판정 전반에서 빠진다** (E-8). 아래 네 곳 전부다.
      "승급만 빼면 된다" 로 좁히면 새는 곳이 있다 — 실제로 확인한 경로를 적는다.

### FR-22: 승급 조건 정정 — 3회 연속 (도메인 변경)

**이번 SPEC2 에서 가장 큰 변경이다.** 판정의 근간이 바뀐다.

- [ ] FR-22.1: **승급 조건은 「단계별 목표를 순차로 3회 연속 통과」 하나뿐이다** (E-12).
      초보자 기준 3회 연속 → 중급자 기준 3회 연속 → 상급자 기준 3회 연속 → **다음 단계로.**
- [ ] FR-22.2: 한 세션에 상급자 기준을 채웠다고 그 자리에서 승급하지 않는다.
      `evaluate.ts:82-84` 의 현재 동작을 대체한다.
- [ ] FR-22.3: **끝까지 수행했으나 기준에 미달한 세션이 나오면 그 기준의 연속 횟수가 0 이 된다** (E-13).

- [ ] FR-22.3a: **'불가능' → 다지기는 연속을 깨지 않는다** (E-15).

      못 채운 것이고, 중단은 도전을 접고 아래 단계를 다진 것이다.
- [ ] FR-22.3b: **다음 세션은 실패한 것을 그대로 다시 시킨다** (E-15).
